# 分院年度營收推算器

純靜態網站（HTML + JS），放在 GitHub Pages；報表資料與參數存在 Firebase Firestore，所有人開啟網址看到的都是管理者最近一次上傳的資料。進入網站需要輸入「進入密碼」，管理功能另有「管理密碼」。

## 檔案
- `index.html`：頁面與樣式
- `app.js`：計算、報表解析、管理功能
- `firebase-config.js`：Firebase 連線設定（要自己填）
- `firestore.rules`：Firestore 安全規則（要貼到 Firebase）

## 一、設定 Firebase（約 5 分鐘）
1. 到 Firebase 主控台建立專案（不需要 Google Analytics）。
2. 左側「建立」>「Firestore Database」>「建立資料庫」，選正式版模式，地點選 `asia-east1`（台灣）。
3. 進入 Firestore 的「規則」分頁，把 `firestore.rules` 的內容整份貼上，按「發布」。（有改版時請重新貼上最新的規則。）
4. 專案設定（齒輪）>「您的應用程式」>「</>」網頁，註冊應用程式後，把畫面上的 `firebaseConfig` 內容貼進 `firebase-config.js`，取代裡面的 YOUR_… 文字。

## 二、上架到 GitHub Pages
1. 建立新的 GitHub repository，把本資料夾的檔案上傳到根目錄。
2. Settings > Pages > Source 選 `Deploy from a branch`，Branch 選 `main`、資料夾選 `/ (root)`，儲存。
3. 幾分鐘後會得到網址：`https://<帳號>.github.io/<repo 名稱>/`，把網址給各分院主管即可。

## 三、使用方式
- **第一次使用**：開啟網址，在輸入進入密碼的畫面按右上角「管理」> 輸入管理密碼 `8888` > 按「建立預設密碼 1234」。接著用 `1234` 進入網站。
- 管理者：進入網站後，右上角「管理」> 輸入管理密碼 `8888` > 選擇報表檔案（.xls / .xlsx）> 確認「資料截至日期」（預設為檔案日期）> 按「發布給所有人」。
- 同一個視窗可修改各分院的「人次推估係數」、「到店率」與「大檔期月份」，按「儲存參數」後所有人即時套用。
- 一般使用者：選分院、調整指標、查看推算結果，不需要密碼；調整只在自己的瀏覽器，不會改到雲端資料。

## 三之二、個人數據
- 選好分院後，可切換「分院整體」或「個人數據」；個人數據用下拉選單選人。報表的「工作表2」會一併讀取（姓名、職稱、到職日與各項指標）。
- 個人的計算方式與分院相同（來客、新客、成交率、客單 → 業績），但個人沒有營收目標，所以沒有達成率；業績以報表的「當月銷售業績」為準。
- 個人的服務人次：管理視窗可另外上傳「金牌信任榜」，系統以「分院＋姓名」對應報表中的同仁，只讀取「總服務人次」欄位作為實際值（來客數 ÷ 服務人次即為該同仁自己的係數，固定不變）。金牌信任榜沒有的人，才用所屬分院係數回推估計，畫面上會標示。到店率仍沿用所屬分院的設定。
- 金牌信任榜可獨立上傳，不影響營運績效報表；之後重新上傳營運績效報表，已上傳的服務人次資料會保留。
- 「自動套入年度剩餘人數預估值」：以個人到職日（或 1/1）到資料截至日的營業日日均推算，再套用該分院「非大檔期／全期間」的比例。
- 舊的資料沒有個人資料，請重新上傳含工作表2的報表。

## 三之一、兩組密碼
- **進入密碼**（預設 `1234`）：所有人進入網站都要輸入。管理者可在「管理」>「網站進入密碼」改成 4 到 20 個英文字母或數字，變更後舊密碼立即失效。
- **管理密碼**（`8888`）：用來上傳報表、修改參數、變更進入密碼。
- 資料存放在以進入密碼命名的文件裡，不知道密碼就讀不到資料。
- 之前版本若已經把資料上傳到雲端（`pub` 集合），新規則發布後該資料不再開放讀取，請用 1234 進入後重新上傳一次報表即可。

## 四、需要定期維護的地方
- **換管理密碼**：`firestore.rules` 裡有兩處 `8888`，一起改掉後重新發布規則。密碼不在網頁程式碼裡。
- **春節公休日**：`app.js` 最上方的 `CLOSED`，每年更新（目前為 2026/2/16–2/20）。
- **預設係數與到店率**：`app.js` 的 `DEFAULT_PARAMS`，只是雲端還沒有設定時的預設值。

## 五、運作規則
- 「自動套入年度剩餘人數預估值」：以「非大檔期月份」的營業日日均為基準（預設排除 5、10 月，管理視窗可改），排除週日與 `CLOSED` 的公休日；新增的新客、舊客與營收都用平常月份的水準計算，視為剩餘日子都是平常月份。資料中沒有月份欄位時，會退回全年日均的簡易算法。
- 資料截至日若不是月底，該月視為未滿月，不納入基準。
- 平均每月預約數：預約數 ÷ 資料截至日經過的月數（例如 11/21 為 10.7 個月）。
- 到店服務人次 = 到店來客數 ÷ 係數；預約數 = 到店服務人次 ÷ 到店率。

## 六、安全性說明
- 兩組密碼都由 Firebase 規則在雲端驗證，不是只在畫面上擋住；但密碼是文件名稱，任何人都能不斷嘗試，所以 4 位數密碼只算基本防護。預設的 1234 非常容易被猜到，請在第一次使用後立刻改成較長的英數字密碼。
- 輸入正確的進入密碼後，密碼會暫存在該瀏覽器分頁的 sessionStorage，關閉分頁就會清除；也可以按右上角「登出」。
- 尚未完成 Firebase 設定時，網站會顯示內建範例資料且不需密碼。
